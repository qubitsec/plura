# 한수원 협력기업 공급망 소버린 사이버시큐리티 통합지원사업

# 공개입찰 추진안 및 제안요청서(RFP) 구성 초안

---

## 문서 목적

본 문서는 ‘한수원 협력기업 공급망 소버린 사이버시큐리티 통합지원사업’을 특정기업과의 수의계약이 아니라 **공정하고 투명한 공개입찰을 통해 추진하기 위한 별도 입찰기획 문서**입니다.

사업의 핵심은 한수원이 146개 협력기업에 단순 장비를 보급하는 것이 아니라, **사업비 전액을 부담하여** 국내 통합 보안플랫폼, 구축, 24시간 국내 보안관제, 사고대응, 교육과 성과평가를 하나의 서비스로 제공하는 것입니다.

한수원과 같이 국가 중요시설 가급 수준의 보안책임을 부담하는 기관의 공급망 보안자료는 국내 법률과 통제 아래 저장·처리되어야 합니다. 이에 데이터·운영·기술·통제·지속성 주권을 국내에 유지하는 **소버린 사이버시큐리티**를 사업의 필수 원칙으로 적용합니다.

# 1. 공개입찰이 필요한 이유

## 1.1 사업의 공공성과 규모

본 사업은 146개 협력기업을 대상으로 하며, 한수원의 전액지원 예산이 투입되고 여러 기업의 보안데이터와 사고대응이 연계되는 대규모 공급망 사업입니다.

따라서 다음 원칙이 필요합니다.

- 공정한 참여기회
- 기술과 가격의 객관적 비교
- 사업자 선정 과정의 투명성
- 장기 운영에 대한 책임성
- 특정 제품이나 업체에 종속되지 않는 요구조건
- 실제 탐지·대응 능력의 사전 검증

## 1.2 장비구매 입찰이 아니라 통합서비스 입찰

입찰대상을 방화벽·EDR·SIEM 등 개별 장비로 분리하면 다음 문제가 발생할 수 있습니다.

- 제품 간 정보가 분리되어 공격흐름을 통합적으로 보기 어려움
- 구축·관제·사고대응의 책임주체가 분산됨
- 협력기업별 설치와 교육을 조정하기 어려움
- 한수원 중앙대시보드와 성과평가의 일관성이 떨어짐
- 사고 발생 시 업체 간 책임공방 가능성

따라서 입찰대상은 다음을 포함하는 **통합 관리형 보안서비스**로 정의하는 것이 바람직합니다.

> 플랫폼 이용권 + 초기진단·구축 + 기업별 온보딩 + 24×365 보안관제 + 사고대응 + 교육·훈련 + 보고·평가 + 계약종료 이관

# 2. 권고하는 계약방식

## 2.1 기본 방향

사업 특성상 단순 최저가 낙찰보다는 기술능력, 관제역량, 다수기업 운영능력, 데이터 분리, 사고대응과 PoC 결과가 중요합니다.

따라서 다음 방식이 우선 검토대상입니다.

> **공개 공고에 의한 제한경쟁입찰 + 협상에 의한 계약**

여기서 제한경쟁은 비공개 수의계약을 의미하지 않습니다. 공개적으로 공고하되 24시간 보안관제, 관련 수행능력, 다수기업 서비스 역량 등 합리적 자격을 갖춘 사업자만 참여하도록 하는 방식입니다.

구체적인 입찰·계약방법은 한수원 계약부서와 법무 검토를 통해 최종 확정해야 합니다.

## 2.2 권고 계약기간

- 기본계약: 3년
- 연차별 성과평가와 예산확정
- 자산 증감에 따른 단가 정산
- 중대한 SLA 미준수 시 시정·감액·해지 조건
- 계약종료 시 2~3개월 이관지원

보안관제는 기준선 학습, 정책 고도화, 기업별 운영정착에 시간이 필요하므로 1년 단기계약보다 다년도 계약이 효과적입니다. 다만 매년 성과평가를 통과해야 다음 연도 수행이 유지되도록 조건을 둘 수 있습니다.

# 3. 전액지원형 통합계약 구조

## 3.1 권고 계약모델

한수원이 공개입찰을 통해 단일 책임사업자를 선정하고, 플랫폼·구축·관제·사고대응·교육·평가를 포함한 전체 서비스에 대해 총괄계약을 체결합니다. 146개 협력기업은 별도의 비용이나 개별 이용계약 없이 참여협약을 체결하고 서비스를 제공받습니다.

> **한수원 단일계약 + 협력기업 무상 참여 + 기업별 보안운영 의무**

### 장점

- 146개 기업의 비용징수·미납·세금계산서·중도정산 업무 제거
- 한수원의 통합관리와 단일 SLA 적용
- 모든 대상기업의 신속하고 동일한 보안기준 적용
- 플랫폼·관제·사고대응 책임주체의 일원화
- 중앙대시보드와 공급망 성과평가의 일관성 확보
- 규모의 경제에 따른 단가 절감
- 비용이 아닌 탐지·대응·개선성과 중심의 사업관리

## 3.2 비용관리 방식

협력기업에 비용을 청구하지 않더라도 예산의 투명성과 자산 증감관리를 위해 제안사는 자산·서비스별 단가를 제출해야 합니다.

- 기업 초기진단·구축 단가
- 웹서비스·서버·PC별 월 단가
- 보안관제와 로그보관 단가
- 교육·훈련·고급 포렌식 단가
- 3년 총소유비용과 연차별 비용
- 자산 증감 시 정산기준과 단가상한
- 데이터 반환·이관·삭제 비용
- 갱신 시 인상률 또는 상한

한수원은 기업별 실제 적용자산을 기준으로 수행사업자와 정산하며, 협력기업에는 별도 청구·세금계산서·미납관리 절차를 두지 않습니다.

## 3.3 협력기업의 비재무적 의무

비용을 전액 지원하는 대신 참여협약에는 다음 의무를 명시합니다.

- 보안책임자·실무담당자 지정
- 대상 자산과 계정정보의 등록·현행화
- 에이전트·정책 설치와 유지
- 중요경보 확인 및 기한 내 조치
- 사고조사·증거수집·포렌식 협조
- 자산·인사·시스템 변경 통보
- 교육·훈련·보안수준 평가 참여
- 개선권고 이행

반복적인 미준수는 비용지원 중단보다 협력기업 보안평가, 개선명령, 특별점검 및 공급망 관리절차에 반영하는 것이 바람직합니다.

# 5. 제안요청서의 핵심 원칙

## 5.1 특정제품명이 아닌 성과요건으로 작성

공개입찰 제안요청서에는 PLURA-XDR 등 특정제품명을 필수조건으로 기재하지 않고 다음과 같은 성과요건을 사용합니다.

- 여러 협력기업을 하나의 중앙체계에서 관리할 수 있을 것
- 기업별 데이터와 권한을 분리할 것
- 웹·서버·PC와 계정·로그 이벤트를 상관분석할 것
- 24시간 보안관제를 제공할 것
- 공격의 탐지뿐 아니라 차단·격리·포렌식을 지원할 것
- 공급망 전체 위험도와 기업별 개선현황을 제공할 것
- 실제 PoC에서 요구 시나리오를 검증할 것
- 계약종료 시 표준형식으로 데이터를 이관할 것

## 5.2 소버린 사이버시큐리티를 필수 성과요건으로 작성

국내 기업이라는 명칭만을 요구하는 방식이 아니라, 국가 중요시설 공급망에 필요한 주권 요건을 객관적인 성능·운영 조건으로 제시합니다.

- 보안 원시로그·분석정보·백업을 대한민국 내에서 저장·처리할 것
- 한수원 승인 없는 국외 이전·해외 관제센터 접근을 금지할 것
- 24시간 관제와 사고대응 책임조직을 국내에 둘 것
- 핵심 탐지·차단 기능이 해외 SaaS·외부 AI API 없이도 지속 동작할 것
- 핵심 플랫폼의 개발·기술지원·정책개선 책임체계가 국내에 존재할 것
- 한수원이 계정·권한·보존·반출·삭제정책을 최종 통제할 것
- 외부 생성형 AI에 보안 원시로그와 기술정보를 직접 전송하지 않을 것
- 해외 재위탁자와 데이터 처리위치를 공개하고 변경 시 사전승인을 받을 것
- 사업자 교체나 해외 서비스 중단에도 표준형식 데이터 이관과 국내 연속운영이 가능할 것

> **국산이라는 사실만으로 낙찰을 결정하지 않되, 국내 기술·국내 데이터·국내 관제·국내 사고대응으로 보안주권을 확보하는 능력은 독립적인 필수 평가요소로 반영합니다.**

## 5.3 과도한 독점요건 배제

다음 항목은 객관적 필요성이 확인되지 않으면 필수자격으로 사용하지 않는 것이 바람직합니다.

- 특정 특허 보유
- 특정제품 또는 특정 클라우드만 허용
- 지나치게 좁은 레퍼런스 조건
- 특정 기능명이나 화면구성을 그대로 요구
- 경쟁사업자가 충족하기 어려운 불필요한 조직·지역 조건

특허나 특정 제품명은 그 자체로 필수자격이 되어서는 안 됩니다. 다만 국내 저장·처리, 국내 관제, 국내 기술지원, 외부 AI 비종속성 등 소버린 사이버시큐리티 요건은 국가 중요시설 공급망의 보안목표와 직접 관련된 객관적 성과조건으로 평가할 수 있습니다. 최종 문구는 한수원 계약·법무 검토를 거쳐 경쟁성과 보안필요성을 함께 충족하도록 확정해야 합니다.

- 운영체제·보안장비·애플리케이션 로그 수집
- 실시간 검색과 장기 보관

# 16. 입찰 추진 시 유의사항

## 16.1 “PLURA를 도입하기 위한 입찰”로 보이면 안 됩니다

입찰의 목적은 특정제품 구매가 아니라 한수원의 공급망 보안목표 달성입니다. PLURA-XDR는 그 목표를 가장 잘 충족한다는 것을 기술제안과 PoC로 증명해야 합니다.

## 16.2 낮은 가격만으로 선정되지 않도록 해야 합니다

146개 기업의 보안관제는 설치 이후의 운영품질이 핵심입니다. 가격배점이 지나치게 높으면 인력·로그보관·사고대응이 축소될 수 있으므로 기술과 PoC 비중을 충분히 확보해야 합니다.

## 16.3 “완벽한 보안”을 요구조건으로 쓰지 않습니다

대신 다음과 같이 측정 가능한 조건을 사용합니다.

- 필수 자산 적용률
- 정상 로그수집률
- 긴급경보 통보시간
- 모의공격 탐지·차단 결과
- 미조치 사고 수
- 데이터 분리와 접근통제
- 계약종료 이관 가능성

## 16.4 데이터 소유권과 이관을 명확히 합니다

원시로그와 산출물은 협력기업 또는 한수원의 관리대상이며, 사업자는 계약기간 동안 위탁처리합니다. 계약종료 시 표준형식 반출과 안전한 삭제를 보장해야 합니다.

## 16.5 기술정보 플랫폼과 보안관제의 역할을 구분합니다

기술정보 전주기 플랫폼은 자료의 전송·보관·활용·반납·파기를 관리하고, 공급망 보안관제는 그 플랫폼에 접근하는 계정·단말·서버와 외부 공격을 감시합니다. 두 사업을 혼동하지 않되 로그와 사고정보는 연계할 수 있어야 합니다.
